The Trade-offs (hover to reveal)

Skills Superpowers

+ Remembers Everything
"Remember when we discussed the auth bug? Fix that in the PR review." Skills can do this. Subagents can't.
+ Instant Activation
Type /commit and boom—skill loaded, action taken. No waiting for a subprocess to spin up.
+ User Commands
Your team can type /review, /commit, /test—like Slack commands but for coding. Subagents are Claude-initiated only.
~ Context Tax
Every skill instruction lives in your context. A 500-line style guide means 500 lines less for actual code.

Subagent Superpowers

+ Messy Work Stays Hidden
Read 100 files to find one answer? The subagent handles the mess. You just see the clean result.
+ Budget-Friendly
The Explore subagent uses Haiku by default (cheap & fast). Why pay Opus prices to grep through 50 config files?
+ Parallel Power
"Explore auth AND database AND API"—three subagents work simultaneously. Skills do one thing at a time.
~ Lossy Compression
You only get a summary back. If the subagent missed something, you won't know. It's a one-way trip.

The Cheat Sheet

Skills = Your Pair Programmer

Like a colleague who sits with you all day, remembers your conversations, and speaks your team's language.

  • User types /command → magic happens
  • Remembers your whole conversation
  • Great for: reviews, commits, debugging
  • Trade-off: uses your context window

Subagents = Your Research Team

Like sending an intern to the library. They do the legwork and return with a summary.

  • Spawns a separate worker (isolated context)
  • Explore agent uses Haiku (fast & cheap)
  • Great for: exploration, docs, planning
  • Trade-off: only returns a summary

Pro tip: They can work together

Skills can run inside a subagent using context: fork. This gives you the best of both: a /command users can invoke, but execution happens in isolated context. Perfect for user-triggered tasks that involve heavy exploration.
